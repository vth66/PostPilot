PostPilot einrichten

Beide Wege von Grund auf: einmal lokal auf dem PC, einmal als Dauerläufer auf der Synology DS218+ unter DSM 7.1. Vorwissen über Docker oder Webserver ist nicht nötig.

Was hier eigentlich läuft

Die Anwendung ist ein einziges Java-Programm mit eingebautem Webserver. Startest du es, horcht es auf Port 8080 und liefert die Oberfläche an den Browser aus. Es gibt keinen externen Webserver, keine Datenbank und nichts zu registrieren. „Port 8080“ ist dabei nur eine Hausnummer auf deinem Rechner — http://localhost:8080 heißt „auf diesem Rechner, Tür 8080“.

Alle Daten — Fotos, Stammorte, fertige Zuschnitte — liegen in einem Ordner. Wo der liegt, steuert eine einzige Einstellung. Das ist der wichtigste Unterschied zwischen beiden Varianten: lokal liegt er im Benutzerprofil, im Container zeigt er auf einen Ordner der NAS.

Variante A — lokal auf dem PC

A1

Java installieren

Du brauchst ein JDK 21. Meldet java -version schon 21.x, überspring diesen Schritt. Sonst Temurin 21 von adoptium.net holen und mit den Vorgaben installieren.

Prüfen: Windows-Taste drücken, cmd tippen, Enter, dann eingeben:

java -version

Es muss openjdk version "21… erscheinen. Steht dort 17 oder 8, ist noch eine ältere Version voreingestellt — dann in der Systemsteuerung unter „Umgebungsvariablen“ JAVA_HOME auf den Ordner von Java 21 zeigen lassen.

A2

Das Programm bauen

Aus dem Quellcode wird eine einzelne Datei postpilot.jar. Zwei Wege, such dir einen aus.

Weg 1 — in IntelliJ, ohne weitere Installation

  1. IntelliJ öffnen, „Open“ wählen, den entpackten Projektordner auswählen (den mit der pom.xml darin), mit „Trust Project“ bestätigen.
  2. Rechts am Rand auf den Reiter „Maven“ klicken.
  3. Dort postpilot → Lifecycle aufklappen und auf package doppelklicken.
  4. Beim ersten Mal lädt Maven die Bibliotheken aus dem Internet — das dauert ein paar Minuten. Am Ende steht unten „BUILD SUCCESS“.

Weg 2 — auf der Kommandozeile

Setzt ein installiertes Maven voraus.

cd C:\dev\postpilot
mvn package

Fertig ist in beiden Fällen die Datei target\postpilot.jar.

A3

Starten

java -jar target\postpilot.jar

Im Fenster rauschen ein paar Zeilen durch. Wichtig ist Tomcat started on port 8080 und darunter die Angabe deines Datenverzeichnisses. Fragt die Windows-Firewall beim ersten Start, reicht „Abbrechen“ — für localhost braucht es keine Freigabe.

Dann im Browser aufrufen:

http://localhost:8080

Die JAR-Datei kannst du hinlegen, wohin du willst — sie ist selbstständig. Ein Doppelklick startet sie allerdings ohne sichtbares Fenster; nimm lieber die kleine Startdatei aus A6.

A4

Beenden

Im Konsolenfenster Strg + C drücken oder das Fenster schließen. Damit ist die Anwendung weg; die Daten bleiben liegen.

A5

Wo deine Daten liegen

%APPDATA%\PostPilot\
   fotos\           die hochgeladenen Originale
   export\          die fertigen Zuschnitte, nach Datum sortiert
   stammorte.json   deine Ortsliste, im Editor bearbeitbar

%APPDATA% kannst du im Explorer direkt in die Adresszeile tippen. Der Ordner wird beim ersten Start angelegt, die Stammorte-Datei mit fünf Beispielorten aus deiner Ecke gefüllt.

A6

Einstellungen, die du vielleicht brauchst

Alles lässt sich beim Start mitgeben, ohne im Code etwas zu ändern:

:: anderer Port, falls 8080 belegt ist
java -jar postpilot.jar --server.port=9090

:: Daten woanders ablegen, etwa auf einer zweiten Platte
java -jar postpilot.jar --postpilot.data-dir=D:\PostPilot

Damit du das nicht jedes Mal tippst, leg neben die JAR-Datei eine Textdatei start-postpilot.cmd mit diesem Inhalt:

@echo off
start "" http://localhost:8080
java -jar "%~dp0postpilot.jar"

Ein Doppelklick startet die App und öffnet gleich den Browser. Soll sie bei jedem Anmelden bereitstehen: Windows-Taste + R, shell:startup eingeben und eine Verknüpfung dieser Datei in den Ordner legen.

A7

Wenn etwas klemmt

„Port 8080 was already in use“
Ein anderes Programm hat die Hausnummer belegt. Starte mit --server.port=9090 und ruf http://localhost:9090 auf.
„UnsupportedClassVersionError“
Es läuft noch ein altes Java. Prüf java -version (siehe A1).
Die Seite bleibt weiß
Schau ins Konsolenfenster. Steht dort eine rote Fehlermeldung, schick sie mir; sonst hilft Strg + F5 im Browser.

Variante B — auf der Synology DS218+ (DSM 7.1)

Hier läuft die App dauerhaft auf der NAS: Sie startet nach einem Stromausfall von selbst wieder, und du erreichst sie aus dem ganzen Heimnetz, auch vom Handy.

Warum dieser Weg und nicht Docker Desktop

Docker Desktop ist ein Programm für Windows, das auf dem PC eine kleine Linux-Umgebung startet, damit du dort Container bauen und laufen lassen kannst. Man braucht es nur, wenn man aus Quellcode ein fertiges Container-Abbild backen will. Das umgehen wir: Statt ein eigenes Abbild zu bauen, nehmen wir ein fertiges Java-Abbild aus dem Internet und legen deine postpilot.jar einfach in einen Ordner, den der Container mitlesen darf. Damit brauchst du weder Docker Desktop noch SSH noch einen Build auf der NAS — alles passiert in der DSM-Oberfläche.

Das passt auch besser zur DS218+: Mit Celeron-Prozessor und 2 GB Speicher wäre ein Maven-Build im Container quälend langsam und könnte mangels Speicher abbrechen. Und der Container Manager mit seinen Compose-Projekten, den die meisten Anleitungen voraussetzen, existiert erst ab DSM 7.2 — du bist auf 7.1.1.

B1

Docker-Paket installieren

Paket-Zentrum öffnen, nach Docker suchen, installieren. Auf DSM 7.1 heißt das Paket noch schlicht so; der Container Manager aus neueren Anleitungen ist dasselbe in neu und gibt es für dich noch nicht.

Bei der Installation legt das Paket einen freigegebenen Ordner docker an. Siehst du ihn danach in der File Station neben home und homes nicht, leg ihn selbst an: Systemsteuerung → Gemeinsamer Ordner → Erstellen, Name docker.

B2

Ordner anlegen

In der File Station unter docker diese zwei Ordner erstellen:

docker/
   postpilot/
      app/     hier kommt die postpilot.jar hinein
      data/    hier legt die App Fotos, Stammorte und Exporte ab

Die Trennung ist Absicht: app ist das Programm und wird bei jedem Update überschrieben, data sind deine Inhalte und bleiben unangetastet.

B3

Programm bauen und hinüberkopieren

Auf dem PC im Projektordner bauen, wie in A2 beschrieben:

cd D:\_AI\Projects\PostPilot
mvn package

Die entstandene Datei target\postpilot.jar in der File Station nach docker/postpilot/app/ hochladen — ziehen und fallen lassen reicht. Der Name muss genau postpilot.jar bleiben, er taucht gleich im Startbefehl auf.

B4

Java-Abbild herunterladen

Docker öffnen, links auf Registrierung. Oben nach eclipse-temurin suchen, den Treffer doppelklicken. Es erscheint eine Auswahl der Varianten („Tags“) — nimm 21-jre und bestätige.

Der Download läuft im Hintergrund und ist etwa 200 MB groß. Unter Abbild siehst du, wann er fertig ist.

Das ist eine fertige Java-21-Laufzeit von Eclipse — dieselbe, die du auch auf dem PC installiert hast, nur eben als Container-Abbild. Dein Programm steckt nicht darin, es wird gleich von außen hineingereicht.

Wenn „Registrierung konnte nicht abgefragt werden“ erscheint

Die Suche im Reiter „Registrierung“ fragt Docker Hub über das Internet ab. Scheitert das, liegt es fast immer an der Namensauflösung der NAS, nicht an Docker. Prüfe in dieser Reihenfolge:

1. Kommt die NAS überhaupt ins Internet? Paket-Zentrum öffnen — lädt die Paketliste? Systemsteuerung → Aktualisieren & Wiederherstellen → „Nach Updates suchen“ — antwortet es? Scheitert beides, ist es ein Netzproblem und nicht Docker.

2. DNS eintragen. Systemsteuerung → Netzwerk → Reiter „Netzwerkschnittstelle“ → LAN markieren → Bearbeiten → „Manuell konfigurieren“ und als DNS-Server die Adresse deines Routers eintragen (meist 192.168.x.1), alternativ 9.9.9.9. Ein vertippter oder leerer DNS-Eintrag ist die mit Abstand häufigste Ursache.

3. Uhrzeit prüfen. Systemsteuerung → Regionale Optionen → Zeit. Geht die Uhr der NAS deutlich falsch, scheitern verschlüsselte Verbindungen, und die Abfrage bricht genauso ab.

4. Docker-Paket neu starten (Paket-Zentrum → Docker → Aktion → Beenden, dann Starten) und die Suche erneut versuchen.

Kommt die NAS nachweislich ins Internet und nur die Suche bleibt stur, lade das Abbild per SSH — das umgeht die Oberfläche vollständig. Wie du dich verbindest und wo der Befehl eingetippt wird, steht Schritt für Schritt unter B9.

B5

Container anlegen

Unter Abbild das Abbild eclipse-temurin:21-jre markieren und auf Starten klicken. Es öffnet sich ein Assistent, der dich über mehrere Seiten führt. Wichtig: Die beiden Ordner aus B2 müssen schon existieren und die postpilot.jar aus B3 muss in app/ liegen — sonst lässt sich weiter unten nichts auswählen und der Container stoppt gleich wieder.

Seite „Netzwerk“

Nichts ändern. bridge ist angehakt, das ist richtig. → Weiter

Seite „Allgemeine Einstellungen“

Containername: postpilot. Haken bei Automatischen Neustart aktivieren — damit kommt die App nach einem Neustart der NAS von selbst wieder hoch. „Ressourcenbegrenzung aktivieren“ bleibt aus.

Auf derselben Seite gibt es die Schaltfläche Erweiterte Einstellungen. Dort hinein, denn hier stehen zwei Dinge, ohne die der Container nicht startet:

Das Feld Befehl ausführen (je nach DSM-Fassung „Befehl“, im Reiter „Umgebung“) bekommt genau das:

java -Xmx768m -jar /app/postpilot.jar

Und in der Tabelle der Umgebungsvariablen zwei Zeilen anlegen:

POSTPILOT_DATA_DIR = /data
TZ                 = Europe/Berlin

Das -Xmx768m deckelt den Speicherhunger von Java. Auf einer NAS mit 2 GB ist das nötig, sonst kann sich die App beim Verkleinern großer Fotos zu viel nehmen. Mit Speichern zurück, dann → Weiter

Seite „Port-Einstellungen“

Lokaler Port 8095, Container-Port 8080, Typ TCP. Steht beim lokalen Port „Auto“, die 8095 von Hand eintragen. Die 8080 belegt DSM teilweise selbst, daher die krumme Zahl. → Weiter

Seite „Volume-Einstellungen“

Zweimal auf Ordner hinzufügen:

docker/postpilot/app    →  Mount-Pfad /app     (Haken bei „Schreibgeschützt“)
docker/postpilot/data   →  Mount-Pfad /data    (kein Haken)

Links der echte Ordner auf der NAS, rechts der Name, unter dem der Container ihn sieht. → Weiter

Seite „Zusammenfassung“

Alles kontrollieren, den Haken bei „Diesen Container nach dem Erstellen des Assistenten ausführen“ stehen lassen, Fertig.

B6

Aufrufen

Unter Container sollte postpilot jetzt auf „Wird ausgeführt“ stehen. Im Browser auf einem beliebigen Gerät im Heimnetz:

http://ITwareNAS:8095

Klappt der Name nicht, nimm die IP-Adresse der NAS (Systemsteuerung → Info-Center → Netzwerk), etwa http://192.168.1.50:8095. Auf dem Handy lohnt sich „Zum Startbildschirm hinzufügen“ — dann sieht es aus wie eine App.

Beim ersten Start legt die App in docker/postpilot/data die Unterordner fotos und export sowie die Datei stammorte.json an. Siehst du die in der File Station, hat alles geklappt.

B7

Aktualisieren, wenn sich der Code ändert

Auf dem PC neu bauen, die neue postpilot.jar nach docker/postpilot/app/ hochladen und die alte überschreiben. Dann in Docker unter Container den Container markieren, Aktion → Neu starten. Mehr ist nicht nötig — das Abbild bleibt, nur dein Programm ist neu.

Der Ordner data wird dabei nicht angefasst. Nimm ihn trotzdem in Hyper Backup mit auf.

B8

Wenn etwas klemmt

Das Protokoll findest du unter Container → Container markieren → Details → Reiter Protokoll. Dort steht im Normalfall dieselbe Startmeldung wie auf dem PC.

„Registrierung konnte nicht abgefragt werden“ beim Suchen eines Abbilds
Kein Docker-Fehler, sondern meist DNS auf der NAS — die vier Prüfschritte stehen im Kasten bei B4, dazu der Weg über docker pull per SSH.
Der Container startet und stoppt sofort wieder
Fast immer stimmt der Startbefehl oder der Dateiname nicht. Prüfe, ob die Datei wirklich postpilot.jar heißt und direkt in app/ liegt (nicht in einem Unterordner target), und ob im Befehl /app/postpilot.jar steht — mit führendem Schrägstrich.
„Unable to find image … manifest unknown“
Der Tag wurde nicht mitgeladen. Unter Registrierung noch einmal eclipse-temurin suchen und gezielt 21-jre wählen, nicht latest.
„Permission denied“ oder die App kann nichts speichern
Dem Ordner data in der File Station Schreibrechte geben (Rechtsklick → Eigenschaften → Berechtigungen). Der Container läuft als root und darf normalerweise schreiben; wenn nicht, liegt es an den Ordnerrechten.
Die Seite lädt nicht
Läuft der Container überhaupt? Sonst Port prüfen: Im Browser muss die 8095 stehen, im Container-Port die 8080. Beides vertauscht ist der häufigste Zahlendreher.
Alles ist zäh beim Hochladen großer Fotos
Erwartbar auf dieser Hardware. Die DS218+ skaliert ein 24-Megapixel-Foto spürbar langsamer als dein PC. Wenn es stört, bleib für die Arbeit am PC und nutz die NAS nur als Dauerläufer.
B9

SSH: wie du überhaupt auf die Kommandozeile der NAS kommst

DSM selbst hat keine Kommandozeile — Befehle für die NAS tippst du in einer SSH-Sitzung, die du von deinem PC aus aufbaust. Das geht so:

  1. In DSM: Systemsteuerung → Terminal & SNMP → Haken bei „SSH-Dienst aktivieren“, Port 22, Übernehmen.
  2. Am PC die PowerShell öffnen (Windows-Taste, „PowerShell“ tippen, Enter). Das ist dein Rechner, noch nicht die NAS.
  3. Verbinden — mit deinem DSM-Administrator-Konto: 
    ssh deinbenutzer@ITwareNAS
    Klappt der Name nicht, nimm die IP: ssh deinbenutzer@192.168.x.y. Beim ersten Mal fragt SSH nach dem Fingerabdruck — mit yes bestätigen. Dann das DSM-Passwort eingeben: es erscheinen dabei keine Zeichen, auch keine Sternchen. Einfach tippen und Enter.
  4. Steht links im Prompt der NAS-Name (etwa deinbenutzer@ITwareNAS:~$), läuft ab jetzt alles auf der NAS.

Dann das Abbild laden — sudo fragt noch einmal nach demselben Passwort, wieder unsichtbar:

sudo docker pull eclipse-temurin:21-jre

Es laufen Fortschrittszeilen durch; am Ende steht Status: Downloaded newer image for eclipse-temurin:21-jre. Mit sudo docker images kannst du es nachsehen, mit exit die Sitzung beenden. Danach liegt das Abbild in DSM unter „Abbild“ und du machst bei B5 weiter.

Meldet die Shell docker: command not found, nimm den vollen Pfad: sudo /usr/local/bin/docker pull eclipse-temurin:21-jre. Verlangt die Anmeldung einen Bestätigungscode, hat dein Konto Zwei-Faktor-Schutz — dann den Code aus der App eingeben. Und sudo funktioniert nur, wenn dein Konto in der Gruppe administrators ist.

Alles in einem Befehl statt über die Oberfläche

Wenn du schon in der Sitzung bist, kannst du dir B5 auch komplett sparen und den Container direkt anlegen:

sudo docker run -d --name postpilot --restart unless-stopped \
  -p 8095:8080 \
  -v /volume1/docker/postpilot/app:/app:ro \
  -v /volume1/docker/postpilot/data:/data \
  -e POSTPILOT_DATA_DIR=/data -e TZ=Europe/Berlin \
  eclipse-temurin:21-jre java -Xmx768m -jar /app/postpilot.jar

Die Ordner aus B2 und die JAR aus B3 müssen trotzdem vorhanden sein. Danach taucht der Container ganz normal in der Docker-Oberfläche auf.

B10

Später, falls du doch auf DSM 7.2 oder 7.3 gehst

Dann bekommst du den Container Manager mit Compose-Projekten, und die beiden Dateien Dockerfile und docker-compose.yml im Projekt werden nutzbar: Projektordner auf die NAS kopieren, Container Manager → Projekt → Erstellen, vorhandene docker-compose.yml verwenden. Das baut die App selbst im Container, lädt also kein fertiges Java-Abbild von außen.

Für die DS218+ ist das trotzdem nicht der bessere Weg — der Build braucht dort viel Zeit und Speicher. Die beiden Dateien bleiben vor allem für den Fall liegen, dass die App mal auf kräftigerer Hardware läuft.

Beide Varianten gleichzeitig?

Geht problemlos — es sind zwei getrennte Installationen mit getrennten Daten. Praktisch ist die Aufteilung: auf dem PC entwickeln und ausprobieren, auf der NAS die Fassung, die du wirklich benutzt.

Was noch nicht drin ist

Die Planung über Metricool fehlt bewusst noch. Dafür sind zwei Dinge zu klären: Metricool holt Bilder nur von einer öffentlich erreichbaren Adresse ab, und einen Instagram-Standort nimmt es nur bei automatischer Veröffentlichung an. Bis dahin ist der Weg: in PostPilot zuschneiden, exportieren, und die Dateien aus dem export-Ordner von Hand in den Metricool-Planer ziehen.
